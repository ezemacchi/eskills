# Project notes

What the skills need to know about the project and do not keep in code: how tickets are named, the workflow and its statuses, how test cases are named, who files what. This is the kit's empty file. A project pack ships its own (`notes.md` in the pack), which replaces this one.

Personal notes go in your own file (`paths.myNotes`), which `notes` prints after the team's. When the board and the notes disagree, the board wins: write the correction in your own notes and tell whoever maintains the pack.
